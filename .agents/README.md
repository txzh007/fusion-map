# .agents 目录规范

本目录用于统一管理 Agent 运行所需的“能力资产”，包括技能文档、模板、流程约束。目标是：**可复用、可追溯、可迭代**。

## 1. 目录结构

```text
.agents/
├─ README.md                      # 本规范（目录总说明）
└─ skills/
   ├─ README.md                   # skills 子目录规范
   └─ fusion-map-agent-skills.md  # 项目级技能定义（当前主入口）
```

## 2. 设计原则

- **单一真源**：同一类规则只保留一个权威文档，避免多处拷贝。
- **最小分层**：先按能力域拆目录（如 `skills/`），不做过度层级。
- **显式命名**：文件名可直接表达用途，避免缩写歧义。
- **向后兼容**：重命名/迁移时先更新引用，再删除旧文件。

## 3. 文件命名规则

- 使用 `kebab-case`。
- 技能主文档命名建议：`<project>-agent-skills.md`。
- 模板类文档命名建议：`template-<topic>.md`。
- 说明类文档命名建议：`README.md`（放在目录根）。

## 4. 变更流程（必须遵循）

1. 在目标目录新增或修改文档。
2. 全局搜索并更新引用链接。
3. 删除旧路径文档（如有迁移）。
4. 最后执行一次“引用完整性检查”（至少 grep 一次旧名和新名）。

## 5. 版本与变更记录

- 文档顶部建议包含：`Owner`、`Last Updated`、`Status`。
- 重大结构调整（目录迁移、命名策略调整）必须在 PR 描述写明。
- 如果同一规范被多个团队消费，建议在文档末尾维护 `Changelog` 小节。

## 6. 质量门禁（Review Checklist）

提交前自检：

- [ ] 是否存在重复规范文件（语义重复）
- [ ] 是否有失效链接或旧路径残留
- [ ] 新命名是否符合 `kebab-case`
- [ ] 是否说明了边界与适用范围
- [ ] 是否给出了可直接执行的步骤

## 7. 当前约定

- `fusion-map-agent-skills.md` 是当前项目 Agent 能力的唯一主入口。
- 后续新增技能文档，统一放在 `.agents/skills/`。
- `plan/` 仅保留计划和引用，不再存放 skills 正文。
